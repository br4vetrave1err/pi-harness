1 — Introduction

This SAD documents the decisions that are hard to reverse: substrate pinning, filesystem-as-bus, stateless projection, and dual-surface parity. Method is first-principles: start from irreducible truths, derive components as minimal mechanisms, then order by build DAG.

How to read
Each component lists owned state, I/O, invariant, and “if it lies” failure — those become SRS musts and test gates (TASKS.md:3).

2 — Goals, Constraints, Assumptions

Goals (in priority)
  1. Observability — any detached pi run stays observable after parent exits (T1).
  2. Parity — HTTP and TTY show the same fleet within one tick (T7).
  3. Determinism — rebuild is cached hit; host edits to .pi/agents live without rebuild (T8).
  4. Safety — bounded inspect, no traversal, no ENOENT crash (T6).
Constraints
  • Pinned ubuntu:24.04, node 22, pi 0.84.4 (Dockerfile:1)
  • Model dots 512k → clamp 390k (Dockerfile:37)
  • Single-host volumes, no external queue
  • sh fallback (Alpine) for dispatch (server.js:398)

4 — Views (Kruchten 4+1)

4.1 Logical view — domain & modules

Layers: Substrate → Runtime → Bus → Projection → Orchestration. Bus is the hinge (file system). Projection never mutates bus except mock shell path with unique runId.

Bounded contexts
  • Fleet (lifecycle, tokens, cost, children)
  • Sessions (chat jsonl, agent tag)
  • Workflow (rounds, verdict)
  • Presentation (cards, modals, stats)
Invariants as types
type FleetState = "running"|"pending"|"paused"|"complete"|"failed"|"stopped"
type DashboardStatus = "running"|"waiting"|"done"|"error"
map: pending→running, paused→waiting, complete→done, failed|stopped→error
stale(lastUpdate, state) = (running|pending && now-lastUpdate>30s) => failed

4.2 Process view — runtime, concurrency, lifetimes

dispatch(POST /api/dispatch)
  ├─ PI mode: spawn('docker',['exec','-d','pi-personal-agent','pi','-p',prompt]) detatched → returns 100ms (server.js:340)
  └─ SHELL mode: mkdir <runId> → write status.json:running → spawn('sh -c … | >> output-0.log') → setTimeout 8s → status:complete (server.js:358)

poll: App.tsx useEffect 1s → GET /sessions + /fleet + /session-stats  (Promise.all)
SSE:  EventSource /api/fleet/stream → fs.watch(SUBAGENT_RUNS) → fleet:changed (500ms)

modal:
  fetch /api/fleet/:id?lines=200 (bounded) → tabs log|transcript|events|artifacts|session
  steer: POST /fleet/:id/steer → supervisor-channels/<runId>.steer.json
  stop:  POST /fleet/:id/stop  → stop.requested
GC: setInterval 60s → delete failed|complete older than 10min (server.js:642)

6 — Qualities, Risks, Evolution

Qualities addressed

  • Availability: entrypoint tail -F survives rotation; heartbeat proves liveness; healthchecks gate deploy.
  • Performance: readdirSync + readFileSync bounded to 20 sessions + GC fleet; memo LogLineView prevents 500 ms full re-render.
  • Safety: 5 MB→500 KB session guard; 64 KB/200 fleet bound; traversal basename + normalize + inside SESSIONS_DIR.
