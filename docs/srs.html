1 — Introduction

1.1 Purpose

This SRS defines what Pi-Harness must do regardless of implementation language. It is the acceptance contract: if any must statement fails, the system does no useful work (axioms T1–T9, TASKS.md:2).

1.2 Scope

Pi-Harness is a deterministic Docker harness that runs a main pi-personal-agent container and a fleet of detached pi subagents, exposing their lifecycle via a shared filesystem bus to two renderers (Web and TTY). Out of scope: LLM training, hosted queue, or external orchestrator — workflow is a JS runs.run() sequence.

2 — Overall Description

2.1 Product perspective

Pi-Harness wraps pi (0.84.4) without forking it. Interaction: host E:/projects/pi-harness ↔ volumes ↔ containers pi-personal-agent + pi-dashboard (+ optional git-sync). No DB; file tailing + SSE/poll is the transport.

Host files ──volume──► Containers (ubuntu:24.04, node22) ── tail/logs ──► docker logs
         │                        ├─ pi-freeflow proxy :390k clamp
         └─ git push ──► GHCR (docker-ci.yml) ── Watchtower/git-sync ──► redeploy

2.2 Product functions

  • Fleet: spawn, observe, steer, stop, and GC subagents via bus files.
  • Dual visibility: Web React and Bash TTY render the same counts/lines within one poll tick.
  • Orchestration: coder→tester loop, 3-round cap, tester reads git diff HEAD~1 not coder narrative.
  • Safety: proxy clamp, bounded inspect (64KB/200), path traversal block, 5 MB session guard.
  • Auto-update: buildx GHCR + Watchtower/git-sync (infra change requires rebuild).

2.3 User characteristics

2.4 Constraints

  • Pinned substrate: ubuntu:24.04, node 22.x, pi 0.84.4 (Dockerfile:1 deterministic).
  • LLM model freeflow/dots-studio/dots-3-note-preview:free advertised 512k → must clamp 390k (empirical Dockerfile:37).
  • BusyBox/Alpine sh not bash for dispatch fallback (server.js:398).
  • Host E:/projects/pi-harness mount is Windows path; inner paths are POSIX.

2.5 Assumptions & dependencies

  • /var/run/docker.sock mounted so pi-dashboard can docker exec pi-personal-agent pi … for PI dispatch (fallback is shell mock).
  • pi-subagents volume is shared; GC does not delete active runs.
  • Git remote @{u} exists for git-sync rev-parse.
